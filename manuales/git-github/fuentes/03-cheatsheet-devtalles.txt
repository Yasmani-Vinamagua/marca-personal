PARTE 1 Git — el control de versiones

    CONFIGURACIÓN INICIAL · una sola vez                                  HISTORIAL Y DIFERENCIAS

 $ git config --global user.name "Tu Nombre"                           $ git log --oneline

    EL DÍA A DÍA: CAMBIOS Y COMMITS                                       RESET, REVERT Y REFLOG

 $ git status                                                          $ git reset --soft HEAD~1

Estado de los archivos (modificados, en stage, sin seguimiento).      Deshace el último commit, conserva cambios en stage.

 $ git add <archivo>                                                   $ git reset --mixed HEAD~1

Añade un archivo específico al stage.                                 Deshace el commit, cambios quedan sin stage (default).

 $ git add .                                                            $ git reset --hard <commit>

Añade todos los cambios al stage.                                        Cuidado: regresa a un commit descartando TODO lo posterior.

 $ git commit -m "mensaje"                                             $ git revert <commit>

Crea un commit con lo que está en el stage.                           Crea un commit que revierte otro (seguro para remotos).

 $ git commit -am "mensaje"                                            $ git reflog

Add + commit en un paso (archivos ya rastreados).                     Historial de TODO: tu máquina del tiempo para recuperar commits
                                                                      "perdidos".

 PARTE 2 GitHub — colaboración

      FLUJO DE TRABAJO · Feature Branch

  1. git switch -c mi-feature crea tu rama.
  2. Trabaja y haz commits.
  3. git push -u origin mi-feature sube la rama.
  4. Abre un Pull Request en GitHub.
  5. Revisión → correcciones → aprobación.
  6. Merge del PR y elimina la rama.
